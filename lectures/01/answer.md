# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：`gemini-3.5-flash-lite` は講座を知らないまま、一般論でもっともらしく答えた。1回目は「Level 1 基礎（コピペ＆実行）／Level 2 応用（一部改変）／Level 3 発展（ゼロから構築）」という難易度別の3段階だと説明し、AI活用講座なら別の3段階かもしれないとも付け加えた。2回目は「難易度別」「AI活用の習熟度」「プロンプトの深さ」の3パターンを挙げ、「通常はレベル3までのコンプリートを目指す」と答えた。どちらも最後は「運営や資料で確認してください」で締めていた。
- 用語集の正しい意味と比べて気づいたこと：`data/glossary.json` の `homework-levels` によると、正しくは「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」の3段階で、**どれか1つに取り組めば完了**し、原則として採点しない。モデルは「基礎・応用・発展」と名前の雰囲気は近く当てたが、中身は推測で、「1つで完了」「採点しない」という講座独自の決まりは知らなかった。特に2回目の「レベル3までのコンプリートを目指す」は正しい内容と正反対なのに、確信を持って書かれていた。同じ質問でも実行ごとに答えの構成が変わり、出力が確率的に揺れること（temperature）と、知らないことをもっともらしく答えること（ハルシネーション）を確認できた。
- 表示できたトークン数（入力 / 出力）：宿題の3レベルの質問で **21 / 691**、「LoRAとは何ですか？」で **7 / 578**（`--chat` の1回目）。入力に比べて出力がはるかに多く、短い質問でも長い回答が返る。`response.usage_metadata` の `prompt_token_count` と `candidates_token_count` を表示している。使用量が返らない場合は「不明」と表示し、実際の0と区別する。

## 宿題

- 取り組んだレベル：実装
- やったこと：`app/ask.py` に `--chat` を追加した。SDKの `client.chats.create(model=MODEL)` で会話を1つ作り、同じセッションに `send_message` で質問を送る。SDKがユーザーとモデルの発言を履歴として保持するため、前の応答を踏まえて追加質問できる。従来の1回だけの質問方法も使える。空白だけの入力ではAPIを呼ばず、`/exit`・`/quit`・入力終了・入力待ち中のCtrl+Cで終了する。会話中にAPIエラー（レート制限の429など）が起きても会話は終了せず、日本語のメッセージを表示して次の質問を受け付ける。SDKは成功した応答だけを履歴に追加するため、失敗した質問は履歴に残らず、そのまま聞き直せる。APIを使わないテスト7件を `tests/test_ask.py` に追加した。
- 結果：Codespaces で `uv run python -m app.ask --chat "LoRAとは何ですか？"` を実行し、続けて「それを具体例で説明して」と質問した。2回目の回答は「それ」が LoRA を指すと理解し、シェフとメモ帳の例え話と画像生成AIでの具体例で LoRA を説明した。会話履歴が引き継がれている。

  | ターン | 質問 | 入力トークン | 出力トークン |
  |---|---|---|---|
  | 1 | LoRAとは何ですか？ | 7 | 578 |
  | 2 | それを具体例で説明して | 592 | 796 |

  2回目の入力 592 は、1回目の質問（7）＋1回目の回答（578）＋2回目の質問（数トークン）とほぼ一致する。毎回、履歴全体をモデルに送っていることが数字で確認できた。テストは `uv run pytest -q` で **18 passed**。
- 気づき・疑問：会話を続けられるのは便利だが、入力トークンは「それまでの全発言の合計」になり、ターンごとに増えていく。この例では2ターン目ですでに入力が約85倍になった。長い会話ではコンテキスト長の上限や無料枠のトークン上限に早く達するので、古い履歴を要約したり削ったりする工夫が必要になりそう。また履歴を持たせても講座固有の知識は増えないので、宿題の3レベルのような質問には、用語集を検索させる仕組み（第3回のツール）が必要だと感じた。履歴は実行中のメモリーだけに保持し、終了すると破棄される。
